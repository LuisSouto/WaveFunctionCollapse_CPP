## Intro

Implementation of the *Wave Function Collapse (WFC)* algorithm in C++. WFC is a procedural generation algorithm that can be used to generate (among other things) images or textures based on a series of constraints either provided by the user explicitly or by an input sample. This library **only** supports the input sample approach.

Please check [this video](https://www.youtube.com/watch?v=A2ODauA1a0M) by Paul Merrell for a nice visual explanation of WFC in case you are not familiar with it (technically Model Synthesis in the video but as Paul Merrell explains the underlying principles are the same). The [original repo by Maxim Gumin](https://github.com/mxgmn/WaveFunctionCollapse) is also a great source to see how it works and the type of images it can generate.

For usage examples of WFC in games please check out [this GDC talk](https://www.youtube.com/watch?v=jV-DZqdKlnE) and [this video by Oskar Stålberg](https://www.youtube.com/watch?v=0bcZb-SsnrA).

## Usage

There is an example provided showcasing usage. Some settings that you may want to play with are:
- Pattern length (N): probably the most impactful setting. Typically a value of 2 or 3 works great, while larger values tend to produce broken images or images that resemble too much the original sample. Although it is case specific, so don't hesitate to experiment.
- Boundary conditions: this is mostly periodicity, i.e. whether it can be assumed that the input image is periodic in the X-axis or Y-axis, or both. You can use the enum `BoundaryCondition` to set this up. In the example provided, the boundary condition is set to none, meaning no periodicity is assumed.
- Image transforms: by default WFC will extract patterns from the original image, but you can also ask it to extract patterns from rotated and mirrored versions of the input sample. This can be done with the enum `SpriteTransforms`. In the example I used the all the transforms, but you can use only a subset or just the identity. If you would like to extract patterns from more than one transform (e.g. identity + rotated 180 degrees), you can add the enum values, such as `SpriteTransforms::IDENTITY + SpriteTransforms::ROTATE_180`. Please check `sprite_transforms.h` for the list of available transforms.
- Force boundary patterns: some images have boundary requirements, such as the sky being on top, or the floor being at the bottom. Another example could be walls all around the image, as in a room or a castle. You can force the boundary of the output image to respect this constraint with the setting `force_boundary_patterns`. If true, then it will enforce those boundaries, otherwise it won't and you may end up will walls on just one side of the room.
- Selection strategy: this one is a bit more technical, and it determines how the next cell to be collapsed in the grid is chosen. In other words, if we just chose a pattern for the tile at (x,y), how do we decide which tile should we collapse next? Two options are available: scanline and minimum entropy. Minimum entropy is the criterion used by Maxim Gumin and mainly what differentiates WFC from Paul Merrel's algorithm Model Synthesis. It computes the entropy of each cell and selects the cell with minimum entropy to be solved next. Cells that are mostly collapsed (i.e. only very few patterns are possible) have less entropy, so this approach targets first the parts of the image that are "mostly solved". Scanline is a sequential selection criterion. If the cell we just collapsed was at (x,y), the next cell chosen will be either at (x + 1, y) or (x, y + 1) depending of whether we reached the end of the row. From a performance point of view, scanline is faster, and for large images significantly faster. Paul Merrel also shows numerical examples in 3D where the entropy criterion is not able to find a correct configuration, while scanline does. On the other hand, Maxim Gumin showed that scanline can produce directional bias because it solves from left to right, while using minimum entropy can lead to more natural-looking images. So it really depends on your needs and your particular use case which one is more suitable. For the scanline approach I added the possibility of a random starting point. Normally it would start at coordinates (0,0) and go (1,0), (2,0), and so on. This can indeed lead to artificial looking images and I found that the random starting point partially alleviates this problem and in some examples it improves success rate.

## How to build

There is a CMake file provided that uses GCC to compile the library. As long as you have these dependencies installed (in particular C++20) you should be able to build the library as follows:
2. Open a terminal and cd to a location where you want to clone the repo.
3. Run the following commands:
```
git clone https://github.com/LuisSouto/WaveFunctionCollapse_CPP.git
cd WaveFunctionCollapse_CPP
cmake -B build/ -DCMAKE_BUILD_TYPE=Release
cmake --build build/
```
You can also use a debug build instead of release if you prefer. The library .so file will be stored in *build/lib*, while the executable for the provided example will be in *build/bin*.

Please keep in mind that I only use Ubuntu and therefore I haven't tested compiling in other operating systems. If you encounter any problems I'm happy to look at the issue together.

## Limitations
Probably the biggest limitation is that currently only 2D is supported. If there is enough interest I'm happy to give a try to the 3D implementation, so please reach out if this is something you would find useful.

Another limitation, as I mentioned in the intro, is that only the texture based approach is implemented in order to define constraints. Moreover, since input images are loaded using the `stbi_load` function, only formats compatible with this function are allowed. This should not pose an issue since most standard formats (.png, .jpg, ...) are allowed as far as I know.

Although, theoretically, WFC supports rectangular patterns NxM, I have only implemented the square case NxN.

There is a backtracking implementation for when the algorithm reaches a contradiction, but it is not very sophisticated and the default setting is to quickly restart from scratch after reaching a few contradictions. For small/medium output images this works fine but it may be an issue for large images. If the algorithm fails repeatedly for your use case feel free to reach out and I will think about improving this part. No promises though :).

## Third-party libraries
Aside from standard C++ libraries, the *stb library* was used to read and write images. In particular, `stb_image.h` and `stb_image_write.h`, which are dual-licensed under the Public Domain and MIT licenses. The code was taken as is from the [stb repo](https://github.com/nothings/stb).

The mixer algorithm used in the `hash_combine` function was taken from [Jon Maiga's mx3 code](https://github.com/jonmaiga/mx3), which has a CC0 license.
